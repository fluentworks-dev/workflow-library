Applies when the repository uses shell scripts, a command-line tool, or CI/CD workflows that deploy.

- Command-line tools: test the logic in modules that import nothing from the command-line framework. Drive the thin command layer with the framework's runner against small real files. A domain error exits with code 1.
- Shell scripts: with no arguments, the usage line prints and nothing runs. Each unset required variable stops the script before any action and is named. Killed midway, the `trap` has removed its temporary files. A `$NAME` outside the template allowlist survives unrendered. An unset optional flag adds nothing to the command line.
- Deployment workflows: the development environment deploys only on a manual trigger, staging on a push to the default branch, production on a published release. Version prefixes differ per environment, because run numbers are shared across workflows and identical prefixes collide in the registry. Every caller of the reusable job passes `secrets: inherit`, or secrets resolve to empty strings; prove it with a step that fails fast on an empty value, never by printing. A pull request build never pushes an image.
- A new required variable is in the template placeholder, the script allowlist, the workflow's environment block, the deployment environment's settings and the documentation table. Check all five.
- The live proof is a run of the development deploy from the branch, linked in the test plan. It reaches outside this workspace: trigger it when the repository's guidance file says a session may; otherwise write it as an exact step. Production and release steps always go to the person.
