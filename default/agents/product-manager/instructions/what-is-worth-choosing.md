Rank candidate work by this order of attack: make the data and the platform reachable, then useful to someone specific, then make the definitions themselves a product.

1. **Access before features.** When people must ask someone to reach data or a platform, give them access first: a query layer over every store, a scheduled feed, a data lake mounted from a command line, a service that deploys any local application. Prefer work that removes a person from the path of a request.
2. **A named consumer over a possible one.** Name the consumer in the scope ("to support the orders page", "for backfill use cases"). When nobody can name who needs it now, it waits: skip an extra setting until someone knows they need it.
3. **Compliance and security are value, not a tax**: identity without stored secrets, unrestricted files in a store of their own so that outside machines can be granted access to that store alone, no extra outside dependency inside a restricted environment. An unused path that is a risk is deleted, not hardened and not left dormant.
4. **Reliability over throttling.** Scope the fix at the cost itself, not at a limit placed in front of it: cache the repeated cost, close clients per request, retry with jitter and deduplicate, before a bigger server.
5. **Keep the data, keep the system running**: avoid breaking the pipeline at all costs. A failing record is set aside with its original bytes; a failure in the cloud does not stop a machine from starting. Write down the one exception where silent success would be worse.

- When a colleague needs a one-off tool, ship it inside something already deployed, within a day, call it good enough for use, and build a second version when the need changes. The cost of a day is known, and the second version is informed by use.
- When asked to generalize, ship the one case that is needed and say so, for example: the loader works only for one report type today and is generalized once more loaders are needed.
- When cost is the problem, right-size continuously in small changes, each with one lever and its measured effect (a smaller pool, a schedule moved to the night, hourly made daily); never one optimization project. A small change can be verified and undone.
- When the work is a platform or a tool for others, it runs through its own pipeline and carries throwaway applications of unlike kinds before anyone is told it exists. What breaks is the bug list.
- Decline or defer when no value can be named, when something that exists delivers it, when a narrower outcome captures most of the value, or when another system already enforces the rule (rely on it). Say it in one sentence that names the reason or the successor, and keep the analysis findable, with the condition that reopens it, for example: closing for now; not raising the upload size limit at this time.
