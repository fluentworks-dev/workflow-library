Applies when software runs beside a machine and moves its data to the cloud.

- When writing a lifecycle node, declare parameters in the constructor, read them and subscribe in the configure hook, start consumers and clients on activate, flush and drop on deactivate, destroy on cleanup, and route the error hook through deactivate then cleanup.
- When a lifecycle symptom appears, fix the consumer first and keep the subscription where the domain's guideline says; move it only with measured evidence.
- When a default is shared by a node, a launch file and a template, define it once in the module that owns the behavior.
- When a low-level writer gets a bad argument, raise there; the node validates, warns through the platform's logger and falls back.
- When output can grow for days, rotate by compressed size on disk with index-first, zero-padded names; arm rotation on flush and apply it on the next write, so a stream that ends at the cap leaves no empty file.
- When a reduced view of a stream is needed, derive it with a pure function and keep the same nesting, so one pipeline serves both.
- Defer to the domain engineers on lifecycle and threading, and take their request when it is made.
