- A value that selects an environment (a URL, a client identifier, a tenant) is required with no code default, so it must exist in every environment before the merge deploys. A tunable is optional with a documented default. Names are the same in every environment; a value that is the same everywhere stays hardcoded and is listed as such.
- A production secret never resolves to a development default (`ignored-placeholder-to-prevent-default-value`), and a target that is not ready fails validation on purpose. Do not fix that failure.
- Runtime variables live in one place, and a change that adds one says where it goes in the infrastructure code. A value for a browser bundle is a build argument, so its step is a rebuild.
- Lanes: development deploys by manual trigger only, as `0.0.1-dev.N`; staging on push to the default branch, as `0.0.0-dev.N`; production on a published release whose tag is the version. Every image also carries the git SHA. One reusable job with typed, described inputs is called by a thin trigger per lane, which binds the environment so its protection gates production; a new deploy environment is one more such trigger with its own version prefix. A merge deploys staging; nothing you do deploys production. Production has a backup slot, swapped by hand.
- A build on a pull request never pushes, because pushing would need cloud permissions the pull request context should not have. A bare push trigger that deploys every branch, or any lane wider than these, is a finding.
- Before merging, read what a push to the default branch triggers. That list is what you watch afterwards.
- A merge leaves a fresh clone working: settings default to the sandbox development environment, so a clone runs after one sign-in, and the role assignments and pre-authorization behind that are documented with a warning; a new setting goes into `.env.example`; tools are pinned exactly in one place so CI and local runs are byte-identical, the package manager at one exact version in CI and in the container file.
- Local setup, each part kept true by the pull request that touches it: editor settings that format on save; a `Makefile` target that fails with `$(error ...)` when the private-index credentials are unset; separate production and development container files, with lock files copied first for layer caching.
- When a contract is generated, commit it and regenerate it in pre-commit so CI fails on drift. At the merge, regenerate on the final head and confirm no diff.
- When a tool's defaults drift and break CI with a wave of new findings, pin the behavior in a configuration file whose header says why and which versions were verified. Do not mass-fix the findings or disable the check.
- When you rerun a check, run it the way CI runs it: a mirrored type-check hook can miss errors the real one finds. State errors that already existed by count.
