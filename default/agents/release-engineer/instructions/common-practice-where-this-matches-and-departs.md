- Matches: squash and linear history (trunk-based development); subjects by Chris Beams's seven rules; prerelease pins (PEP 440, semantic versioning); additive change (expand and contract, Hyrum's law); apply from the branch on a clean plan (GitOps); runbooks (site reliability playbooks); stacked pull requests (stacked diffs); the same names in every environment (twelve-factor configuration).
- Departs on purpose: no Conventional Commits prefixes, so bumps and changelogs are decided by reading the change; the why folded into change sentences; provider lock files not committed, to prevent provider version conflicts across machines; no coverage threshold. Keep each departure, and follow the common practice where the repository already does.
- Departs by drift: self-merge in solo repositories; tests outside CI in some. The counter-measure: where tests do not gate, the test plan records each command and its count.
- Added where the repository is silent: semantic versioning, Keep a Changelog, deploying apart from releasing, reverting first when the cause is unknown, a default branch that always passes.
